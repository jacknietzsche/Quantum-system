# 1. 架构总览

## 1.1 架构原则

```
┌──────────────────────────────────────────────┐
│              架构核心原则                       │
├──────────────────────────────────────────────┤
│ 1. AI 作为编排者, 非参与者                      │
│    - Master Agent 做计划, 调 Skills, 汇总结果  │
│    - Specialist Agent 只做单一领域深度分析       │
│                                                │
│ 2. Skill 是一等公民                             │
│    - 所有能力封装为 Skill, 统一 Tool Calling 接口│
│    - Agent 不直接操作数据, 只调用 Skill          │
│                                                │
│ 3. Human-in-the-loop 硬约束                     │
│    - 分析仅在用户手动触发后开始                  │
│    - 关键决策节点可暂停等待确认                  │
│                                                │
│ 4. 可观测性内置                                 │
│    - 每次 Agent Run 全程 Tracing               │
│    - 每个 Skill 调用记录 latency/tokens/result  │
│                                                │
│ 5. 日频优先, 简单至上                           │
│    - 不做实时, 不做 tick 级                     │
│    - 流程固定, 异常清晰                         │
└──────────────────────────────────────────────────────┘
```

## 1.3 技术栈

| 层 | 技术 | 说明 |
|----|------|------|
| 前端 | Vue 3 + TypeScript + Element Plus + ECharts | 重写为对话式 UI |
| 后端框架 | FastAPI (Python 3.11+) | 保留 |
| Agent 框架 | LangGraph + custom Tool Calling | 轻量编排 |
| LLM | 统一通过 `llm_clients/` 抽象层 | 保留现有 6 provider |
| 数据库 | SQLite + SQLAlchemy 2.0 | 保留，精简表 |
| 数据源 | 保留 `providers/sources/` 13 个适配器 | 几乎不变 |
| 邮件 | aiosmtplib (QQ 邮箱 SMTP) | 新增 |
