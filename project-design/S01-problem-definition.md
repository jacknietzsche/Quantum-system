# S1 — 问题定义与现状分析

## 1.1 当前系统的核心问题

| 问题 | 严重程度 | 根因 | 新系统如何解决 |
|------|----------|------|----------------|
| 多因子打分+LLM润色 | 致命 | 规则引擎+美化输出，无真正推理 | 12个Agent协作推理+结构化辩论 |
| super_workflow.py 2355行 | 严重 | 单文件无法维护 | LangGraph状态机，每个Agent独立模块 |
| 数据源不稳定 | 中等 | 多个源中部分经常不可用（tickflow/baostock/eastmoney等） | 6个提供商(10个适配器)+断路器+自动故障转移+SQLite缓存 |
| 无学习闭环 | 致命 | 决策记忆未被使用 | 决策日志→反思→注入后续分析 |
| Skills浅层注入 | 中等 | 23+Skills仅做增强层 | Skill按需加载，改变决策结构 |
| 前端Vue3 | 中等 | 与后端耦合 | React/Vite独立构建 |

## 1.3 核心设计命题

**如何让AI像一个极其专业的投资人一样工作？**

专业投资人的工作模式映射到Agent：

| 专业投资人行为 | 对应Agent | 工具 |
|---------------|-----------|------|
| 看盘面、技术指标 | 市场分析师 | K线数据、技术指标API |
| 研读财报、估值 | 基本面分析师 | 财务数据API |
| 跟踪新闻、政策 | 新闻分析师 | 新闻搜索API |
| 感知市场情绪 | 情绪分析师 | 社交/资金流API |
| 构建看涨论据 | 看涨研究员 | 所有分析报告 |
| 构建看跌论据 | 看跌研究员 | 所有分析报告 |
| 综合判断、裁判 | 研究经理 | 辩论记录 |
| 制定交易计划（入场价/止损/止盈/仓位） | 交易员 | 投资计划 |
| 风险审查（机会成本） | 激进分析师 | 交易提案 |
| 风险审查（下行风险） | 保守分析师 | 交易提案 |
| 风险审查（风险收益比） | 中性分析师 | 交易提案 |
| 最终拍板（确定性约束+LLM决策） | 投资组合经理 | 风险评估+交易计划 |
