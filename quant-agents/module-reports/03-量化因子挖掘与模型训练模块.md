## 一、模块概述

本模块聚焦于 **自动化量化因子挖掘** 与 **大模型量化微调训练**，包含微软研究院 RD-Agent 和社区项目 QuantLLM。与交易决策框架不同，这两个项目专注于量化研究的"基础设施层"——因子发现、模型训练、回测验证。

## 二、核心架构分析

### 2.1 RD-Agent：自动化量化研究循环

**架构模式**：Research + Development 迭代循环（OAPE 架构）

```
[R] Propose new ideas / hypotheses
    ↓
[D] Implement ideas as executable code
    ↓
[Run] Execute code in isolated environment (Docker)
    ↓
[Evaluate] Get feedback (metrics, errors, results)
    ↓
[Knowledge Base] Store learnings → feed back into [R]
    ↓
    (loop continues)
```

**核心模块**（`rdagent/` 目录）：

| 模块层 | 路径 | 说明 |
|--------|------|------|
| **核心框架** | `core/` | `evolving_framework.py`、`evolving_agent.py`、`proposal.py`、`developer.py`、`evaluation.py`、`knowledge_base.py` |
| **组件层** | `components/` | Agent/Coder/Proposal/Runner/Workflow 等可复用构建块 |
| **场景层** | `scenarios/` | 领域特定实现：`qlib/`（金融）、`data_science/`、`kaggle/`、`general_model/`、`rl/`、`finetune/` |
| **LLM层** | `oai/` | LiteLLM 后端抽象，支持 OpenAI/DeepSeek/Azure 等多供应商 |
| **应用层** | `app/` | CLI 入口 + 各场景启动器 |
| **监控UI** | `web/` | Web UI + Streamlit UI 双监控面板 |

**技术差异化**：

| 差异化点 | 说明 |
|---------|------|
| **R&D 循环，非仅编码** | 传统 Agent 只实现给定需求，RD-Agent 自主提出新假设并验证 |
| **数据为中心的量化自动化** | 自动化因子发现和模型演化全流程，非传统因子库 |
| **因子-模型协同优化** | 交替优化因子和模型，产生比单独优化更好的鲁棒性 |
| **真实执行反馈** | 在 Docker 中实际运行生成代码，获取真实指标驱动下一轮改进 |
| **MLE-bench 榜首** | OpenAI ML 工程基准测试 #1，超越 AIDE 等专业 ML 自动化 Agent |
| **论文到代码流水线** | 可读取学术论文，提取模型架构并自动实现 |

### 2.2 QuantLLM：从数据到实盘的全栈量化 LLM 训练

**架构模式**：数据流水线 → 模型训练 → 实盘交易 三层架构

```
┌──────────────────────────────────────────┐
│          数据流水线层                      │
│  crawl_ashare.py（4市场爬虫）              │
│  convert_all_to_training.py（训练数据转换）│
│  generate_*.py（数据增强）                 │
│  merge_and_retrain.py（合并 → 119k样本）   │
└──────────────────────────────────────────┘
                    ↓
┌──────────────────────────────────────────┐
│          模型训练层                        │
│  QLoRA Fine-tune on Qwen2.5-14B           │
│  Unsloth + TRL SFTTrainer                 │
│  rank=32, bf16, early stopping            │
│  → export_gguf.py（GGUF 部署格式）         │
└──────────────────────────────────────────┘
                    ↓
┌──────────────────────────────────────────┐
│          实盘交易层                        │
│  规则引擎预过滤 → Qwen 模型排序            │
│  东方财富 HTTP API 执行                   │
│  三层风控：事前/事中/事后                  │
└──────────────────────────────────────────┘
```

**关键技术指标**：

| 指标 | 数值 |
|------|------|
| 基础模型 | Qwen2.5-14B |
| 微调方法 | QLoRA (rank=32) |
| 训练样本 | ~119k ChatML 格式 Q&A pairs |
| 技术指标系统 | 28 个纯 pandas/numpy 指标（无 ta-lib 依赖） |
| RAG 系统 | FAISS + BAAI/bge-large-zh-v1.5 embedding |
| 回测结果（2005-2025） | 股票策略总收益 +1201%，年化 12.99%，Sharpe 0.383 |
| 基准对比 | 沪深 300 同期总收益 +122%，年化 6.08% |
| 运行环境 | 单卡 RTX A5000 24GB |
| 核心策略 | **均值回复/反转策略**（基于 IC 分析：A 股技术因子全部负 IC） |

**全市场覆盖**：

| 市场 | 标的数量 | 数据源 |
|------|---------|--------|
| A股 | ~5000 只 | 东方财富 HTTP API |
| 期货 | ~80 个 | 东方财富 HTTP API |
| ETF | ~800 只 | 东方财富 HTTP API |
| 可转债 | ~400 只 | 东方财富 HTTP API |

**风控体系**：

| 阶段 | 措施 |
|------|------|
| 事前 | 单仓位 10% 上限、日 20 笔交易限制、幂等去重、kill-switch 文件 |
| 事中 | 双源实时价格故障切换、二阶段执行（先卖后买） |
| 事后 | 完整交易记录、日志日归档、DPO 偏好优化 |

## 三、技术亮点

### 3.1 RD-Agent 的场景插件架构

```python
# 核心框架提供抽象基类，场景层提供具体实现
core/scenario.py → scenarios/qlib/  # 金融量化
                 → scenarios/kaggle/ # 竞赛
                 → scenarios/med/    # 医学
                 → scenarios/rl/     # 强化学习
```

这种设计使得相同的 R&D 循环框架可以应用于完全不同的领域，无需重写框架。

### 3.2 QuantLLM 的 IC 分析驱动策略

```
关键发现：A 股所有主要技术因子均呈现负 IC
→ 趋势跟踪策略在 A 股无效
→ 均值回复/反转策略是 A 股的有效范式
→ 全策略体系围绕反转逻辑构建
→ 回测 20 年验证：+1201% vs 沪深 300 +122%
```

### 3.3 因子-模型协同优化（RD-Agent）

```
传统方法：固定因子集 → 优化模型
RD-Agent：因子提议 → 模型训练 → 因子改进 → 模型再训练（交替循环）
           ↑__________________________________________↓
```

### 3.4 全离线运行能力（QuantLLM）

- 无任何云 API 依赖（含推理）
- 单卡 RTX A5000 完成训练和推理
- 本地 28 个技术指标计算（无 ta-lib）
- 本地 RAG（FAISS + BGE embedding）

## 四、协同价值分析

### 4.1 互补关系

| 能力维度 | RD-Agent | QuantLLM |
|---------|----------|----------|
| 因子发现 | ✅ 自动化闭环 | ❌ 固定反转策略 |
| 模型训练 | ❌ 使用现有 LLM | ✅ QLoRA 全流程微调 |
| 回测验证 | ✅ Qlib 集成 | ✅ 自定义回测 |
| 实盘执行 | ❌ | ✅ 东方财富 API |
| 多市场因子 | ✅ 全市场 | ✅ 4 市场 |
| 策略多样性 | ✅ 可探索多策略 | ❌ 单策略（反转） |
| 代码隔离 | ✅ Docker 沙箱 | ❌ 本地运行 |
| 知识积累 | ✅ Knowledge Base | ❌ |

### 4.2 融合推荐

```
RD-Agent（因子发现 + 回测）
    → 产出：经过验证的有效因子集
    → 输入到 QuantLLM 的训练流水线
    → 产出：微调后的量化交易模型
    → 接入 TradingAgents 的决策框架
```

## 五、局限与改进方向

| 项目 | 主要局限 | 改进方向 |
|------|---------|---------|
| RD-Agent | 需 Docker 环境；学习曲线陡峭；因子可解释性不足 | 增加因子可视化归因；简化部署 |
| QuantLLM | 单策略限制；需 GPU；数据源单一（仅东方财富） | 扩展多策略；支持云端推理；多数据源降级 |
